# Онлайн-сервис аренды спортивного и туристического снаряжения

Учебный проект: бэкенд на **Java 17 + Spring Boot 3** и простой сайт (фронтенд) на HTML/CSS/JavaScript.
База данных — встроенная **H2**, ничего устанавливать кроме Java не нужно.
Сущности и эндпоинты взяты из практической работы по «Технологии проектирования информационных систем».

## Что такое бэкенд и фронтенд

- **Бэкенд** — серверная часть на Java: хранит данные в БД, считает цены, проверяет права, не даёт забронировать одно и то же дважды.
  Отвечает на запросы данными в формате JSON.
- **Фронтенд** — сайт, который видит пользователь: каталог, формы, кнопки. Он отправляет запросы бэкенду.
  Здесь он лежит в `src/main/resources/static` и отдаётся тем же сервером, поэтому запускать нужно одну программу.

Отдельно есть **Swagger UI** (`/swagger-ui.html`) — страница для ручной проверки API без сайта.

# Пошаговая проверка

## Этап 1. Подготовка (один раз)

1. Проверьте, что установлена Java 17 или новее. В терминале: `java -version`.
   Если команды нет — установите JDK (например, Eclipse Temurin 17 или 21) и перезапустите терминал.
2. Нужен либо **IntelliJ IDEA** (Community подойдёт), либо **Maven** (`mvn -v`).
   В IntelliJ Maven уже встроен — это самый простой путь.
3. Распакуйте архив `rental-backend.zip` в папку без кириллицы и пробелов в пути, например `C:\projects\rental-backend`.

## Этап 2. Открыть проект и запустить

**IntelliJ IDEA:**
1. File → Open → выберите папку `rental-backend` (где лежит `pom.xml`) → Open as Project → Trust Project.
2. Подождите, пока внизу справа закончится загрузка зависимостей (индикатор прогресса). В первый раз — несколько минут, нужен интернет.
3. Если IDEA спросит про Lombok / annotation processing — согласитесь (Enable). Если нет, то Settings → Build, Execution, Deployment → Compiler → Annotation Processors → галочка Enable.
4. Откройте `src/main/java/ru/rental/RentalApplication.java` и нажмите зелёную стрелку слева от `public static void main` → Run.

**Консоль:** в папке проекта выполните `mvn spring-boot:run`.

**Признак успеха** — в консоли появились строки:
```
Started RentalApplication in ... seconds
Созданы демо-данные
```
Не закрывайте окно с запущенной программой, пока проверяете. Остановка — красный квадрат в IDEA или Ctrl+C.

## Этап 3. Посмотреть сайт

Откройте в браузере **http://localhost:8080**.

Должен появиться каталог с четырьмя объявлениями (палатка, велосипед, лыжи, байдарка). Попробуйте:
- фильтр по категории или городу → «Найти»;
- клик по карточке → страница объявления (описание, занятые даты, отзывы).

## Этап 4. Сквозной сценарий по трём ролям

Вход хранится в браузере и общий для всех вкладок, поэтому для трёх ролей откройте **три окна**:
обычное окно, окно инкогнито (Ctrl+Shift+N) и окно другого браузера.

Готовые аккаунты (клиента заранее нет, его нужно создать через «Регистрация», роль «Клиент»; если база уже создавалась раньше, удалите папку data рядом с pom.xml):

| Роль | Email | Пароль |
|---|---|---|
| Партнёр | partner@partner.partner | partner123 |
| Администратор | admin@admin.admin | admin123 |

Идём по шагам. После каждого шага проверяйте результат, он указан справа.

| № | Кто | Что сделать | Что должно получиться |
|---|---|---|---|

должна появиться красная плашка «На эти даты снаряжение уже занято». А в каталоге при фильтре по этим датам палатки быть не должно.

## Этап 5. Проверка API через Swagger

Откройте **http://localhost:8080/swagger-ui.html**. Здесь можно вызвать любой из 45 эндпоинтов.

1. `POST /auth/login` → Try it out → `{"email": "partner@partner.partner", "password": "partner123"}` → Execute. Скопируйте `token` из ответа.
2. Кнопка **Authorize** вверху справа → вставьте токен → Authorize.
3. Теперь вызывайте запросы от имени партнёра, например `GET /partner/bookings`. Для клиента сначала создайте его через `POST /auth/register`.
4. Чтобы сменить роль — снова login другим аккаунтом и новый токен в Authorize.
5. Проверьте ошибки: запрос без токена должен вернуть 401, запрос клиента на `/admin/disputes` — 403.

## Этап 6. Посмотреть данные в БД

Консоль H2 по умолчанию выключена. Чтобы включить, в `application.properties` поставьте `spring.h2.console.enabled=true`, перезапустите и откройте **http://localhost:8080/h2-console**:
JDBC URL `jdbc:h2:file:./data/rental`, пользователь `sa`, пароль пустой → Connect.
В левой колонке таблицы `USERS`, `LISTING`, `BOOKING`, `REVIEW`, `DISPUTE`, `NOTIFICATION` и другие. Пример запроса:
```sql
SELECT b.id, l.title, b.date_from, b.date_to, b.status, b.paid
FROM booking b JOIN listing l ON l.id = b.listing_id;
```
Если запущено из IDEA, путь `./data` — это папка проекта. Чтобы начать с чистой БД (заново создадутся 18 демо-объявлений с картинками), остановите приложение и удалите папку `data`. Загруженные партнёрами фото лежат в `data/uploads`.

## Если что-то не работает

| Симптом | Что делать |
|---|---|
| `Port 8080 was already in use` | Закройте то, что занимает порт, либо в `application.properties` поставьте `server.port=8081` и открывайте `localhost:8081` |
| IDEA красным подчёркивает `getId`, `setName`, `@Getter` | Не включён Lombok: Settings → Compiler → Annotation Processors → Enable, затем File → Invalidate Caches / Restart |
| Maven не скачивает зависимости | Нужен интернет; проверьте VPN/прокси, нажмите в IDEA Maven → Reload All Projects |
| `release version 17 not supported` | Старая Java: поставьте JDK 17+ и выберите его в File → Project Structure → SDK |
| Сайт: «Не удалось связаться с сервером» | Приложение не запущено или упало, смотрите консоль |
| Сайт показывает старую версию после правок | Ctrl+F5 в браузере |
| Любая другая ошибка при запуске | Скопируйте первые строки с `ERROR` / `Caused by` из консоли и пришлите — разберёмся |

# Описание проекта

## Правила бизнес-логики

- Даты бронирования включительные; стоимость = цена за сутки × число дней; залог = 30 % (настройка `app.deposit-percent`).
- Нельзя бронировать на прошлое и на даты, занятые подтверждёнными или выданными бронированиями. При подтверждении проверка повторяется.
- Статусы: `pending → confirmed → (оплата) → active → completed`; `disputed` — вернули с повреждением; `cancelled` — отмена или отказ.
- Снаряжение можно выдать только после оплаты. Отменить можно только `pending` и `confirmed`.
- Отзыв — только по завершённому бронированию. Клиент оценивает объявление и партнёра, партнёр — клиента. Один такой отзыв на бронирование. Рейтинг пользователя пересчитывается автоматически.
- Объявления непроверенного партнёра создаются как `pending` и не видны в каталоге, пока админ не подтвердит партнёра.
- `DELETE /listings/{id}` не стирает запись, а скрывает объявление (`hidden`), чтобы сохранилась история.
- Администратором через регистрацию стать нельзя.
- Администратор может скрыть объявление (статус `blocked`, «Скрыто администрацией»): партнёр видит это в списке и в уведомлении и не может ни изменить, ни вернуть такое объявление. Вернуть его может только администратор.
- Каждое уведомление хранит ссылку на то, о чём оповещает: нажатие ведёт на нужную страницу и подсвечивает нужную заявку (например, партнёр из уведомления о новой заявке попадает сразу к ней).
- Фото к объявлению партнёр загружает файлом (JPG, PNG, WEBP, GIF до 5 МБ, формат проверяется по содержимому) или вставляет ссылкой. В демо-данных 18 объявлений с картинками.
- Защита от перегрузки: ограничение числа запросов с одного адреса, блокировка входа на 5 минут после 5 неверных паролей, лимиты длины всех полей, пессимистическая блокировка объявления при бронировании, единый обработчик ошибок без вывода внутренностей сервера.

## Структура проекта

```
src/main/java/ru/rental/
├── RentalApplication.java      точка входа
├── model/                      сущности БД и enum'ы статусов
├── repo/                       репозитории — доступ к БД (Spring Data JPA)
├── service/                    бизнес-логика
├── web/                        контроллеры — HTTP-эндпоинты, обработка ошибок
├── dto/Dto.java                формы запросов и ответов (JSON)
├── auth/                       токены, проверка ролей (@Auth), текущий пользователь
└── config/                     настройки, демо-данные
src/main/resources/
├── application.properties      настройки (порт, БД, залог ...)
└── static/                     сайт
    ├── index.html
    ├── css/style.css
    └── js/
        ├── main.js             меню и переключение страниц
        ├── api.js              запросы к серверу и хранение входа
        ├── util.js             вспомогательные функции
        └── views/              страницы: каталог, объявление, бронирования, кабинет партнёра, админка ...
```

Схема слоёв бэкенда: **запрос → Controller → Service → Repository → БД**.

Аутентификация: при входе выдаётся случайный токен (таблица `auth_tokens`, живёт 7 дней), сайт присылает его в заголовке
`Authorization: Bearer <token>`. Пароли хранятся как BCrypt-хеш. Права задаются аннотацией `@Auth(Role.PARTNER)` и т. п.

## Что можно добавить

- пагинация каталога;
- хранение загруженных фото во внешнем хранилище;
- PostgreSQL вместо H2 (меняется `application.properties` и зависимость в `pom.xml`);
- JWT и Spring Security вместо собственных токенов;
- автотесты.
